\chapter{Introduction}
\label{sec:intro}

This book is an introduction to chip design using open-source tools. It covers the steps needed to produce a chip for a design described in a hardware description language (HDL), down to the files that are sent to the fab. Those steps are often called the backend design.

\section{Tool Installation}

The magic of open-source tools is that we can install them on a personal computer without any concerns of licensing and license servers. The downside of open-source tools is the variety of installation options. There is no single best way for the installation. Furthermore, open-source tools are best supported on a Unix operating system, and preferably Linux. Support under MacOS comes second. MS Windows is best served by using the Windows Subsystem for Linux.


\subsection{Nix Based}

From OpenLane-2 on, the preferred installation is \myref{https://en.wikipedia.org/wiki/Nix_(package_manager)}{Nix}-based. Nix is a cross-platform package manager, also enabling native binaries for ARM-based systems (e.g., Mac laptops). The OpenLane 
\myref{https://openlane2.readthedocs.io/en/latest/getting_started/common/nix_installation/index.html}{getting started} documentation explains how to install Nix, and also how to set up the Nix cache for the OpenLane tools.

Another option to install Nix is via \myref{https://docs.determinate.systems/}{Determinate}. Note that you need to install the OpenLane cache to avoid building all the tools yourself.

\subsection{Docker Images}

Another option is to use Docker containers with ready-installed tools.
Harald Prettl, from the Johannes Kepler University of Linz, provides 
\myref{https://github.com/iic-jku/IIC-OSIC-TOOLS}{IIC-OSIC-TOOLS} (Integrated Infrastructure for Collaborative Open Source IC Tools), a Docker container based on Ubuntu 24.04 LTS for the following
CPU architectures: x86\_64/amd64 and aarch64/arm64.

Note that, as the time of writing, the default PDK is the IHP PDK, which is not yet supported in the OpenLane flow from within the container.\footnote{See: \url{https://github.com/iic-jku/IIC-OSIC-TOOLS/issues/147}} Switch to the Sky130 PDK with the following command:

\begin{verbatim}
sak-pdk sky130A
\end{verbatim}


\subsection{Compiling from Source}

As the tools are open-source, it is always a (theoretical) option to compile them from source. However, often there are library dependencies that are not easy to resolve. Therefore, we recommend installing the tools with some packaging software that ensures compatibility between the various tools.


\subsection{Installing LibreLane}

When you use the \code{nix}-based setup, you need to install \myref{https://github.com/librelane/librelane}{LibreLane}. Install LibreLane by cloning it:

\begin{verbatim}
git clone git@github.com:librelane/librelane.git
\end{verbatim}

\noindent You set up your environment by entering \code{nix} as follows:

\begin{verbatim}
cd librelane
nix-shell
\end{verbatim}

\noindent The frontend command is \code{librelane}. Check the version you have installed with:

\begin{verbatim}
librelane --version
\end{verbatim}

\subsection{Further Packages}

There are several other distributions of the open-source chip design tools available:

\item[\myref{https://yowasp.org/}{YoWASP}] (Yosys WebAssembly Synthesis \& PnR) is a collection of tools targeting FPGA design flow compiled to WebAssembly. Therefore, they can be run easily on different platforms, even as a VSC plugin. 
\end{description}

\section{Open-Source Production Frameworks}

Chip design consists of several steps from synthesis down to GDSII files. Scripts usually orchestrate those steps. In the following, we describe different frameworks that contain the needed open-source tool, but also the scripts to run the flow.

\subsection{OpenROAD}

\myref{https://github.com/The-OpenROAD-Project}{OpenROAD}~\cite{OpenROAD} started as a DARPA-sponsored project to enable an end-to-end design flow of chips from RTL to the final chips without human intervention, within a maximum of 24 hours. The documentation is published on \myref{https://openroad.readthedocs.io/en/latest/}{Read the Docs}.
OpenROAD includes the following open-source \myref{https://openlane.readthedocs.io/en/latest/flow_overview.html}{tools}:

\begin{itemize}
\item \myref{https://github.com/the-openroad-project/openroad/tree/master/src/ifp}{ifp} defines the core are, the rows, and the tracks.
\item \myref{https://github.com/the-openroad-project/openroad/tree/master/src/pdn}{pdn} is a power distribution network (PDN) generator.
\item \myref{https://github.com/the-openroad-project/openroad/tree/master/src/tap}{Tapcell} inserts tapcells or endcaps.
\item \myref{https://github.com/the-openroad-project/openroad/tree/master/src/gpl}{gpl} performs global placement. The tool is an extension of the \myref{https://github.com/The-OpenROAD-Project/RePlAce}{RePlAce} tool.
\item \myref{https://github.com/the-openroad-project/openroad/tree/master/src/rsz}{Gate Resizer} to optimize the design until the maximum utilization is reached.
\item \myref{https://github.com/the-openroad-project/openroad/tree/master/src/dpl}{OpenDP} performs detailed placements.
\item \myref{https://github.com/the-openroad-project/openroad/tree/master/src/cts}{TritonCTS 2.0} is performs clock tree synthesis.
\item \myref{https://github.com/the-openroad-project/openroad/tree/master/src/grt}{FastRoute} performs global routing.
\item \myref{https://github.com/the-openroad-project/openroad/tree/master/src/drt}{TritonRoute} performs detailed routing.
\item \myref{https://github.com/the-openroad-project/openroad/tree/master/src/rcx}{OpenRCX} performs parasitics extraction.
\item And some more.
\end{itemize}

Use the links for documentation of the individual tools.

\subsection{OpenLane}

\myref{https://github.com/The-OpenROAD-Project/OpenLane}{OpenLane}~\cite{OpenLANE, openlane:woset:2020} is a collection of EDA tools, such as Yosys, Magic, Netgen, and KLayout. It also includes OpenROAD. OpenLane consists of TCL scripts to automate the flow from RTL, described in Verilog, to the chip production data as a GDSII file.

OpenLane was developed by eFabless, and the documentation is published on \myref{https://openlane.readthedocs.io/en/latest/}{Read the Docs}.

\subsubsection{OpenLane2 and LibreLane}

\myref{https://github.com/efabless/openlane2}{OpenLane2} is a new, partly rewritten,\footnote{OpenLane2 started out of OpenLane and OpenROAD scripts} framework for chip design with a focus on substituting TCL scripts with Python scripts. The documentation is published on \myref{https://openlane2.readthedocs.io/}{Read the Docs}.
However, the original OpenLane \myref{https://openlane.readthedocs.io/en/latest/}{documentation} is richer than the OpenLane2 documentation. Therefore, consider reading that one as a basis.

Efabless, the original developer of OpenLane and OpenLane2, exited the business in spring 2024. To continue the development of OpenLane, the repository was cloned/forked in April 2025, and the project was renamed to \myref{https://github.com/librelane/librelane}{LibreLane}.
